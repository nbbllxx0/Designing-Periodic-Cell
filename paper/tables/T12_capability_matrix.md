- Source: `results/verification/v2/T12_v2.csv` (counts per capability group and interface), recounted from `results/verification/v2/matrix.csv` (443 rows, 159 distinct checks); cell = (pass + refused as expected) / rows. V2 protocol and expectations were written before the run (`results/verification/v2/NOTES.md` section 1; `expectations.csv`, `expectations_transport.csv`).
- Totals: 267 pass, 144 refused as expected, 32 fail. 31 failures are V2 expectation or design errors (amm was correct) and 1 is an app/ bug; no failure is an amm bug. Every failed row stays in the matrix with its cause.
- The 31 V2 errors: 26 rows were replaced by an addendum (S16, S17) whose expectations were written before it ran; its 30 rows all met their expectation (17 pass, 13 refused as expected). 1 row (`combo_export`) had a wrong JSON path; the corrected predicate holds on the same report.json (`posthoc_checks.json`, checked post hoc). 4 rows (`fam_all_bounds`) had a wrong `n_cells` expectation while the verdict predicate held; they were not re-run.
- The app/ failure (`gui_health`: /api/health showed the mock schema and code hash in live mode) was fixed after V2 ("Post-V2 fixes" in the V2 NOTES): /api/health now reports `amm.tools.SCHEMA_VERSION` and `amm.tools.code_hash()` in live mode (mock mode keeps the mirror's amm-tools/2). The matrix row stays `fail` as recorded.
- Before run 1, a probe on the library found three amm bugs (`negative_G_min`, `zener_target` and `hz_partial_check`); they were fixed before any matrix row ran (results/software/NOTES_V2_fixes.md).
- Replay: 170 of 170 V2 session logs replay exactly; the static PA12 certificate is identical through MCP, GUI, CLI and tutorial 02 (result hash d47062dbaab89457). Test suite after V2: 174 passed, 1 skipped (the skip passed when rerun alone).
- Interfaces: lib = Python library (`amm.tools.Session`); mcp = MCP server driven by a client with no LLM; gui = live GUI HTTP API; gui-edge = clicks in headless Edge; cli = `python -m amm.cli` (added in V2).
