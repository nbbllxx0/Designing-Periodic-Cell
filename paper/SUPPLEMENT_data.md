# Supplementary data dictionary

Generated by `scripts/paper/docs2.py` (run `scripts/paper/make_all.py`) from the files themselves: column names and keys are read, row counts are counted (the claims ledger's count is taken after its final row is registered). Units come from an explicit field-to-unit table per file (`UNITS` in docs2.py), not from the column-name suffix; a column shown with '-' has no unit: a count, flag, label or identifier, a normalized quantity (stiffness / E_s, f* = f a / c_t, lengths / a) or a dimensionless ratio or fraction, as the description says. Which files are released is decided by the release script (plan B7); this list covers the files the paper's tables and figures read.

Common conventions: designs are {family, kind, params} with params as fractions of the cell edge a; `spec_hash` = first 16 hex of sha256 of the sorted design JSON; code identity `code_hash` and checker identity `checker_hash` are 16-hex prefixes of sha256 over the source files (amm/tools.py, amm/certify.py).

## Session logs and certificates

- `session.jsonl` (every session directory): one header record (code and checker identity, schema, profile), then one record per tool call with arguments, result or error, state hash and timing. `amm.tools.replay` re-runs it and compares results and state hashes.
- `certificates/<spec_hash>_<target_key>.json`: the certificate (spec, targets, solver settings, checker hash, blocks static/bloch/as_built, verdict, robust). The certificate JSON embeds the checker hash; the session header records the tool-code identity. Retain both for complete session provenance (V6 NOTES 8.4).
- `exports/<name>/`: cell.stl and tiled_3x3x3.stl (binary STL, mm), report.json (amm-export/1: outcome, certificate reference, screening, disclaimers, file hashes).
