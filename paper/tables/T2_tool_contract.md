- Contract amm-tools/3 (17 tools; profile B 14, profile C 17); results carry the outcome schema amm-outcome/1. Source: `results/software/contract_amm-tools-3.json` (written by `scripts/software/write_contract.py`).
- Outcomes: Certified candidate (`certified_candidate`); Information needed (`need_info`); Not found in families (`not_found_in_families`); Numerically undetermined (`numerically_undetermined`); Proven infeasible (`proven_infeasible`); Refuted candidate (`refuted_candidate`). Five are physical outcomes; `need_info` stops the session and asks.
- Refusal rule (profile C; not applied in ablation profile B): NOT_FOUND_IN_FAMILIES needs one of atlas_not_found, search_not_found; OTHER needs one of bound_violation, atlas_not_found, search_not_found, certificate_undetermined, certificate_refuted; PROVEN_INFEASIBLE needs one of bound_violation; UNDETERMINED needs one of certificate_undetermined.
- Interfaces: every tool is called through `amm.tools.Session.call` (Python library); the MCP server (`amm/mcp_server.py`) registers the tools of the session's profile; the browser GUI backend (`app/`) calls the same Session; the command line (`amm/cli.py`, added in V2) passes its arguments unchanged to `Session.call`. Interface acceptance through library, MCP, GUI and CLI: table T12 (V2).
- 'Changes spec' = the tool mutates the session's specification (logged and replayable).
- Added in schema 2: certify: outcome; evaluate: results C derived C_MPa; get_session: schema_version evidence budget.as_built budget_used.as_built; submit: outcome_card submitted.outcome submitted.evidence.
- Added in schema 3: evaluate: args bands, results bands.
